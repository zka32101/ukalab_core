# AI下書きコンテンツの扱い

AI が下書きした問題・解説・シナリオは、人(専門家)が確認するまで「下書き」として扱う。

## データの印

- `contentStatus: "ai-draft"`(体験型教材。例: it_passport の `it_staff_story.dart` が `isAiDraft` を判定)。問題データでは `tags` の `ai-draft`。
- `source: "original"`(自作。過去問・公式問題・教材の転載ではない)。
- `sourceRef`: 自作である旨を書く(it_passport の検証は `sourceRef` に「自作」を含まないと失敗する)。出典の書名・版が分かる場合はそれも。
- 数値(金額・日数・割合・法令の数値)は、**確認済みのものだけ**使う。確認できない数値は書かない。

## 画面表示

- 下書きのシナリオを開く画面に「**学習用の架空シナリオ(AI下書き・専門確認前)**」と表示する(it_passport / infosecmanage の定数 `k…StoryDraftNotice`)。

## 専門確認後

1. 人の確認結果(OK)を受けて `ai-draft` を外す。「修正」は直して再確認が済むまで残す。
2. 画面の注記も外す(データの印とそろえる)。
3. 記録は確認日(年月)と確認者区分のみ。氏名は記録しない。
4. 広告表現(「別の角度で」等)の根拠には、`ai-draft` を除いた問題だけ数える。

## テスト

- 禁止語検査テスト: 「公式」「本試験相当」「合格保証」など、ストア表記で禁止する語が、ユーザーに見える文言・データに入っていないことを検査する。
- データ検証テスト: `contentStatus`・`source`・`sourceRef`・`termId` の存在、章数・選択肢数を検査する。
- 実装例は各アプリの `test/` を参照(禁止語の一覧の置き場所は要確認)。

詳細な手順: [expert_review_workflow.md](expert_review_workflow.md)。

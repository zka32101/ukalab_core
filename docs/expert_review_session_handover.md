# 専門家役ローカルセッション用 引継ぎ文

運営者が、ローカルの Claude セッションに「専門家役（一次チェック担当）」を任せるための文章。
**AI による一次チェックは人の専門家確認の代わりにならない**。結果は「疑義の洗い出し」として扱い、`ai-draft` タグは外さない。

## 貼り付け用プロンプト（そのまま渡す）

```
あなたは「うかラボ」シリーズの問題データの一次チェック担当（専門家役）です。
対象リポジトリの docs/expert_review/review_ai_draft.csv と、問題 JSONL（assets/questions/*.jsonl）を読み、
各問を次の観点で確認してください。

観点: ①正解が事実として正しいか ②正解が1つに定まるか ③誤答が確実に誤りか（用語の入れ替わり・条件次第で正しい選択肢がないか）
④設問文が曖昧・誘導的でないか ⑤出題範囲（公開シラバス）に対応するか ⑥実在の過去問・公式サンプルに酷似していないか（気づいた範囲）。

ルール:
- 判定は OK / 修正 / 削除 のいずれか。「根拠」（資料名・版・条文。URL可）を書けない問題は OK にせず、コメントに疑義だけ書く。
- 推測で OK にしない。確信が持てないものは「修正」ではなく空欄＋コメント「要・人の確認」とする。
- 優先順位（★）の問題から先に。時間が足りなければ優先分だけで構わない。
- データ(JSONL)や ai-draft タグは編集しない。出力は CSV（列は元の CSV と同じ）と、疑義のある問題の要約（id・理由・修正案）のみ。
- 氏名・所属・連絡先・Drive の URL など個人を特定する情報は書かない。
- 試験の公式問題・教材の本文を転載しない（根拠は資料名と版のみ）。
- このアプリは非公式。「公式」「本試験相当」「合格保証」等の表現を提案しない。

出力: docs/expert_review/review_result_YYYYMM.csv（判定・コメント・根拠を埋めたもの）と summary.md。
```

## 運営者側の手順
1. 各リポジトリの `docs/expert_review/review_ai_draft.csv`（G検定 60／ITパス 271／情セマネ 36）を渡す。優先順位は `expert_review_requests.md` の各節を参照。
2. 返ってきた CSV の「修正」「削除」は、**人の専門家の確認を経てから** 別 PR でデータに反映（`contentVer` 更新）。
3. `ai-draft` を外すのは人の専門家が OK を出した問題のみ。AI 一次チェックの OK だけでは外さない。
4. 広告の「観点を変えた出題」の根拠は `ai-draft` 除外後の付与率で再計算（`docs/marketing_concept.md`）。

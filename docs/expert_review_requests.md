## 0. 汎用の依頼文（そのまま送れる／固有名詞・URL・連絡先なし）

> ご多忙のところ恐れ入ります。学習用アプリ（非公式）に収録する問題・解説の**事実確認**をお願いできないでしょうか。
>
> - 対象: AIが下書きした問題（選択式）と解説、または漢字の意味・読みのデータです。件数は添付の一覧のとおりで、**優先順位の高いものから**で構いません（一部だけのご確認でも助かります）。
> - 確認していただきたいこと: ①正解が事実として正しいか ②正解が 1 つに定まるか（他の選択肢が確実に誤りか）③紛らわしい選択肢が別解になっていないか ④用語・表記・言い回しが適切か ⑤出題範囲として妥当か ⑥実在する試験問題に似すぎていないか（気づいた範囲で）。
> - 回答方法: 添付の表（CSV）の「判定」欄に **OK／修正／削除** のいずれかを入れ、「コメント」「根拠」（資料名・版・条文など。分かる範囲で）を書いて返送してください。根拠を示せない場合は「OK」にせず、コメントだけでも構いません。
> - 内容は**当方が独自に作成した学習用の文章**で、試験の主催団体・出版社等の**公式の問題・教材ではありません**（非公式）。
> - 個人を特定する情報（お名前・所属など）の記入は不要です。ご回答は内容の修正にのみ利用し、お名前を公開することはありません。
>
> 作業量の目安: 1 問あたり 1〜3 分程度です。お手すきの際にご協力いただければ幸いです。

## A. 共通の確認観点（全アプリ共通）

| # | 観点 | 見てほしいこと |
|---|---|---|
| 1 | 事実の正確さ | 正解・解説の記述が現行の制度・規格・用語と一致するか（版・改正日に注意） |
| 2 | 正解の一意性 | 正解が 1 つだけか。他の選択肢のどれかが「条件次第で正しい」になっていないか |
| 3 | 誤答（ディストラクタ）の曖昧さ | 誤答が確実に誤りか。紛らわしい用語対の説明が入れ替わっていないか |
| 4 | 文言 | 設問文が曖昧・誘導的でないか。「最も適切」の基準が文中で分かるか |
| 5 | 出題範囲 | 当該試験のシラバス／出題区分に対応するか（範囲外・旧版のみの内容でないか） |
| 6 | 過去問との類似 | 実在の過去問・公式サンプルに酷似していないか（気づいた範囲で。判断できなければ空欄） |

### 判定の凡例（回答表共通）

| 判定 | 意味 |
|---|---|
| OK | 修正不要 |
| 修正 | 内容の修正が必要（修正案を「コメント」に） |
| 削除 | 出題に不適（理由を「コメント」に） |

回答テンプレート（すべてのアプリ共通。CSV の列と同じ）:

| id | 判定（OK/修正/削除） | コメント | 根拠（資料名・版・条文・URL可） |
|---|---|---|---|
| （例）xxx-0001 | 修正 | 解説の「…」は「…」が正確 | （資料名・版） |

## B. 回答の反映方法（共通）

1. 返送された表を運営者（またはアシスタント）が受け取り、**判定が出た問題だけ**を別 PR でデータ修正する（`contentVer` を更新）。
2. `OK` の問題のみ、`tags` から `ai-draft` を外す。`修正` は直したうえで**再確認が済むまで**タグを残す（軽微な表記修正で、レビュアーが修正後の文面も `OK` とした場合は外してよい）。`削除` は `disabled: true` にするか行を削除する。
3. 確認済みの記録は「確認日（年月）」と「確認者区分（例: 専門家確認）」だけを各アプリの確認記録ファイル（情セマネは `docs/content_review_checklist.md` の判定欄）に残す。**氏名・連絡先・所属は記録しない**。
4. 根拠として挙がった資料名・版は備考に記す（著作物の本文は転記しない）。
5. 広告表現の判定（`ai-draft` を除いた付与率）は、タグを外した後に再計算する。

## C. レビュー範囲外（レビュアーが確認しなくてよいこと）

- アプリの画面・操作性・デザイン、ゲーム要素、課金、広告。
- 問題の難易度の妥当性、出題頻度、配点、合格ライン。
- 誤字脱字以外の「文章の好み」（意見があれば自由記述でよいが必須ではない）。
- 法律・商標・著作権の最終判断（類似の気づきだけで可）。
- データ構造（JSON のキー、タグ名、ID 体系）、集計・統計。
- シラバス改訂の予測、将来の試験での出題可能性。
- 件数が多い場合の**全件確認**（優先リストの範囲で構いません）。

## 9. CSV へのエクスポート（機械利用）

選択式問題は `tools/export_review_csv.py`（標準ライブラリのみ）を使う。**実データには実行していない**（合成データで動作のみ確認）。出力列: `id, 観点, 問題文, ア〜エ, 正解, 解説, 判定, コメント, 根拠`（`sourceRef` など内部情報は出さない。UTF-8 BOM 付きで Excel でそのまま開ける）。

```bash
# G検定: ai-draft 60 問
python3 tools/export_review_csv.py <g-kentei>/assets/questions/g_kentei.jsonl --tag ai-draft -o g_review.csv
# G検定: 優先 11 問だけ
python3 tools/export_review_csv.py <g-kentei>/assets/questions/g_kentei.jsonl --ids 0716 0718 0722 0728 0732 0737 0754 0764 0766 0767 0768 -o g_priority.csv
# ITパス: ai-draft 71 問
python3 tools/export_review_csv.py <it_passport>/assets/questions/it_passport.jsonl --tag ai-draft -o it_review.csv
# 情セマネ: 科目B追加分 36 問
python3 tools/export_review_csv.py <infosecmanage>/assets/questions/info_security.jsonl --id-range 1038 1073 -o is_review.csv
# 簿記: 優先 19 問（j/c 系列で番号が重なるため、先に grep で絞る）
grep -E '"qid": ?"boki3-(j-01(2[2-9]|3[0-4])|c-003[3-8])"' <boki>/assets/exam/boki3.questions.jsonl > /tmp/boki_pri.jsonl
python3 tools/export_review_csv.py /tmp/boki_pri.jsonl -o boki_review.csv
```

`--ids` / `--id-range` は `qid` 末尾 4 桁の数字で判定する。簿記の journal 型（仕訳）は `choices` を持たず `prompt` と `journalAnswer` で構成されるため、CSV の選択肢欄は空になる（正解の仕訳は別途人が読める形にして渡すこと）。

```bash
jq -r 'select((.tags // []) | index("ai-draft")) | [.qid, .prompt] | @csv' assets/questions/g_kentei.jsonl
```

awk -F'\t' '!/^#/ && ($2=="needsReview"||$2=="blank"){printf "%s,%s,%s,,,\n",$1,$2,$3}' scripts/data/kanji_meaning_draft_source.tsv > kanji_meaning_review.csv

## 2. 単位の整理と、サーキの扱いの食い違い（オーナー決定が必要）

読んだ事実:

- `UkalabCharacters.circa` は `appIds: {'g_kentei', 'it_passport', 'info_security', 'gen_ai_passport'}`（情報系4）で定義されている（コードより）。値は資格id と同じ綴り。
- 仕様書では、サーキは「ITパスポート用」で、動機は「ITパスポートのテクノロジ分野（ハードウェア・基盤）」。「1資格に1体」も決定事項。
- つまり「1資格に1体」と「サーキを4資格（4アプリ）で共用」は両立していない。共用先のうち、G検定・生成AIパスポート（分野はAI）や情報セキュリティ（守り）は、回路・ハードウェアのモチーフとの結びつきが弱い（推測）。

### 選択肢

| | A: 情報系はサーキ共用（現状のコードどおり） | B: 資格ごとに専用（推奨） |
|---|---|---|
| 内容 | it_passport, g_kentei, info_security, gen_ai_passport の4資格はサーキ1体。他の13資格は専用 | サーキは it_passport 専用。残り16資格すべてに専用キャラ |
| 新規キャラ数 | 13体 | 16体 |
| 総キャラ数（サーキ含む） | 14体 | 17体 |
| 「1資格に1体」 | 情報系4資格だけ例外（決定事項の修正が要る） | そのまま満たす |
| 画像量の目安（1体 A+B で約1〜1.5MB、仕様書 §6.5） | 約13〜20MB 増 | 約16〜24MB 増 |
| コード | 変更なし | `circa.appIds` を `{'it_passport'}` にする1行（後続PR） |
| 懸念 | モチーフと資格の関連が弱い。AI・セキュリティのアプリで「回路ネコ」が出る | パッケージ容量。全アプリに全キャラの画像が入る（現状 `assets/mascot/` 全体で約18MB） |

推奨: B。理由は、決定事項の「1資格に1体」と「分野に関連するモチーフ」をそのまま守れるため。容量の懸念は、公開順を分ける（§7）ことと、新規キャラは A+B（36枚）までにして C（小物）を省くことで抑える案がある。どちらもオーナー判断。

A を選ぶ場合は、情報系4資格に使う回路ネコのままでよいか（G検定・生成AIパスポートの絵柄が回路で違和感がないか）をオーナーが決める。

## 5. 資格別の企画案

共通:

- 見た目は丸みのあるシルエット、やわらかい線、やさしい表情の少しかわいらしいタッチ。成人向けなので幼くしすぎない。
- 各案の「Lv1→Lv5」は、成長が見た目に表れるようにした。Lv が変わっても変えない特徴は、画像担当が3〜4点固定する。
- 避ける点は、各案固有のもの。共通で、公式キャラ・著名キャラ・企業ロゴ・実在人物に似せない、「公式」「認定」を連想する意匠（団体ロゴ、紋章、試験団体の配色の再現）を使わない、資格名の文字を画像に入れない。
- 動物種は、既存4体（人2・犬・猫）と重なりにくいものを選んだ。「要確認」は、名前・見た目について類似・商標の検索が必要な点。
- id は英小文字・数字・アンダースコアのみ。

1. 分野キーワード3つ（本書 §5）。
2. モチーフ2〜3案（本書 §5）。
3. 類似・商標の検索（オーナー側。結果は本書に記録せず、確定した名前・id だけを仕様書に反映）。
4. オーナー決定（Q1〜Q6）。
5. 確定したキャラごとに、仕様書 §8 の引継ぎ文（サーキ用）を元に、キャラ別の引継ぎ文を作る（別PR）。
6. 画像は別セッション（画像担当）、コード取り込みは本リポジトリ側（別PR、minor バージョン）。この文書の PR ではタグも付けない。
